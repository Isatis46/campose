# Campose — کامپوز

اپلیکیشن اندرویدی برای بازسازی ژست و کادر یک عکس، با Kotlin و CameraX.
عکس انتخابی به‌صورت راهنما روی پیش‌نمایش زنده قرار می‌گیرد؛ **فقط تصویر دوربین در گالری ذخیره می‌شود**.
برنامه آفلاین است و هیچ عکس یا اطلاعاتی را به سرور ارسال نمی‌کند.

## قابلیت‌ها

- انتخاب عکس با Photo Picker سیستم؛ بدون درخواست دسترسی عمومی به گالری.
- تنظیم شفافیت از ۰ تا ۱۰۰ درصد، مستقل از خروجی دوربین.
- حرکت با یک انگشت؛ تغییر اندازه و چرخش هم‌زمان با دو انگشت.
- قفل کردن عکس مرجع با خاموش‌کردن «ویرایش مرجع»؛ سپس لمس پیش‌نمایش برای فوکوس و حرکت دو انگشتی برای زوم دوربین.
- اسلایدر مستقل زوم در هر دو دوربین، تعویض دوربین جلو و عقب در صورت وجود.
- کادرهای ۲۸، ۳۵ و ۵۵ میلی‌متری در دوربین عقب.
- بازنشانی، تغییر و حذف عکس مرجع؛ حفظ مرجع و تنظیمات هنگام بازسازی Activity.
- ذخیرهٔ JPEG در `Pictures/Campose`؛ عکس دوربین جلو مانند پیش‌نمایش آینه‌ای است.
- کنترل دسترسی دوربین، خطاهای بازکردن تصویر و ذخیره‌سازی؛ نمایش فارسی و راست‌به‌چپ.

## استفاده

۱. دسترسی دوربین را فعال کنید و «انتخاب عکس» را بزنید.
۲. شفافیت و جای عکس را تنظیم کنید. با دو انگشت عکس را بچرخانید یا تغییر اندازه دهید.
۳. «ویرایش مرجع» را خاموش کنید تا عکس ثابت بماند؛ کادر، فوکوس و زوم دوربین را تنظیم کنید.
۴. با دوربین جلو یا کمک فرد دیگری، ژست را هماهنگ کنید و «ثبت عکس» را بزنید.
۵. عکس ثبت‌شده را در گالری، پوشهٔ Campose مشاهده کنید.

در اندروید ۸ و ۹، دسترسی نوشتن در حافظه هنگام اولین ذخیره درخواست می‌شود. اندروید ۱۰ به بالا برای ذخیرهٔ عکس‌های خود برنامه به این دسترسی نیاز ندارد.

## معنای گزینه‌های لنز

اعداد ۲۸، ۳۵ و ۵۵، **فاصلهٔ کانونی معادل دوربین فول‌فریم ۳۵ میلی‌متری** هستند، نه تضمین وجود سه لنز فیزیکی مجزا.
برنامه با خواندن فاصلهٔ کانونی و اندازهٔ حسگر، نسبت زوم مناسب را تخمین می‌زند و آن را در محدودهٔ مجاز CameraX اعمال می‌کند.
در صورت نبود اطلاعات معتبر، مبنای تقریبی ۲۶ میلی‌متر استفاده می‌شود و پیام توضیحی نمایش داده می‌شود.
اگر یک کادر خارج از محدودهٔ سخت‌افزار باشد، نزدیک‌ترین زوم انتخاب و محدودیت اعلام می‌شود.
تعویض لنز فیزیکی در دوربین منطقی، در صورت پشتیبانی، به سیستم دوربین گوشی واگذار می‌شود؛ روی بعضی دستگاه‌ها این گزینه‌ها صرفاً برش دیجیتال هستند.
برش حسگر، لرزش‌گیر و پردازش سازنده ممکن است کادر واقعی را کمی تغییر دهند.

## ساخت و نصب

- Android Studio با پشتیبانی AGP 8.9.2، JDK 17، Android SDK 35 و Build Tools 35.0.0.
- Gradle Wrapper نسخهٔ 8.11.1 با بررسی SHA-256 در مخزن قرار دارد.
- حداقل اندروید: **۸ (API 26)**؛ رابط فعلی برای استفادهٔ عمودی روی گوشی طراحی شده است.

پروژه را در Android Studio باز کنید و SDK را معرفی کنید، یا `ANDROID_HOME` را تنظیم کنید:

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

APK خروجی آزمایشی با کلید debug امضا می‌شود. برای انتشار فروشگاهی باید تنظیمات امضای release با کلید خصوصی خودتان اضافه شود؛ کلید خصوصی را وارد مخزن نکنید.

### محیط ابری لینوکس

```bash
bash scripts/setup-cloud.sh
source scripts/cloud-env.sh
```

اسکریپت ابزارها را خارج از مخزن در `/workspace/toolchains` نصب می‌کند، گواهی پراکسی محیط را به مخزن اعتماد جاوا اضافه می‌کند، SDK را آماده می‌کند و build/test/lint را اجرا می‌کند. اعتبارسنجی TLS و checksum غیرفعال نمی‌شوند.
برای شل‌های بعدی، `source scripts/cloud-env.sh` کافی است.
هر وظیفهٔ ابری از قبل محیط ایزوله دارد؛ از checkout موجود استفاده کنید و بدون درخواست صریح، Git worktree نسازید.

## معماری شی‌گرا

| کلاس | مسئولیت |
|---|---|
| `CameraController` | قرارداد مستقل کنترل دوربین |
| `CameraXController` | چرخهٔ عمر، انتخاب دوربین، زوم، فوکوس و ثبت تصویر |
| `LensZoomCalculator` | محاسبات مستقل فاصلهٔ کانونی و محدودیت زوم |
| `PhotoStore` | تنظیم مسیر و متادیتای ذخیره در MediaStore؛ بدون دسترسی به مرجع |
| `ReferenceImageRepository` | بارگذاری غیرهم‌زمان، کاهش مصرف حافظه و اصلاح جهت EXIF |
| `ReferenceOverlayView` | ترسیم عکس راهنما و دریافت ژست‌ها |
| `OverlayTransform` | هندسهٔ مستقل حرکت، مقیاس و چرخش حول محل انگشتان |
| `CameraViewModel` | وضعیت مرجع و بازیابی تنظیمات با SavedStateHandle |
| `CameraActivity` | اتصال رابط، دسترسی‌ها و هماهنگی اجزا |

کادر Preview و ImageCapture از یک ViewPort مشترک استفاده می‌کنند. ثبت عکس مستقیماً با ImageCapture انجام می‌شود و هیچ screenshot یا ترکیبی از Viewها ذخیره نمی‌شود.

## تست‌ها

```bash
# تست‌های محاسبات زوم و تبدیل‌های هندسی، همراه بررسی Android Lint
./gradlew :app:testDebugUnitTest :app:lintDebug

# نیازمند گوشی یا شبیه‌ساز API 29+ با دوربین فعال و دسترسی ADB
./gradlew :app:connectedDebugAndroidTest
```

تست‌های دستگاه شفافیت واقعی ۰/۵۰/۱۰۰، جابه‌جایی در Canvas، کاهش اندازهٔ عکس بزرگ، تعویض دوربین جلو و عقب و ثبت JPEG بدون ورود عکس مرجع به خروجی را بررسی می‌کنند.
در GitHub Actions، build، تست واحد و lint اجرا و APK ذخیره می‌شود؛ تست دوربین نیاز به دستگاه دارد.

در اجرای اولیهٔ این نسخه، ساخت APK، هر ۱۳ تست واحد و هر ۴ تست دستگاه روی شبیه‌ساز AOSP اندروید ۱۰ (API 29) موفق شدند؛ تستی رد یا نادیده گرفته نشد. Android Lint خطایی نداشت و ۳ هشدار دربارهٔ جهت عمودی ثابت و تنظیمات پشتیبان‌گیری جدید اندروید گزارش کرد. امضای APK نیز با `apksigner verify` بررسی شد.

موارد نیازمند بررسی روی گوشی واقعی: رفتار لنزهای فیزیکی و لرزش‌گیر هر سازنده، کیفیت زوم، فوکوس، شباهت کادر به فاصلهٔ کانونی انتخاب‌شده و کیفیت نوردهی. شبیه‌ساز جایگزین این بررسی‌ها نیست.
